# 開工接續助手

新對話開始時，幫使用者快速進入「上次做到哪」的脈絡，避免從零開始解釋。

## 核心原則
1. **不主動 git pull**（避免覆蓋使用者本地未 commit 變動，只提醒「要不要 pull」）
2. **若 vault 沒對應工作筆記就回報 + 詢問**，不亂建檔
3. **跟 `/收工` skill 是「對偶」關係**：收工存進去、開工讀出來

## 開工 SOP（依序執行）

### 步驟 1：判斷工作目錄
- 從 `$PWD` 取得當前目錄
- 確認是否是 git repo（`.git` 目錄存在）
- 記下 `REPO_NAME=$(basename "$PWD")`
- 若非 git repo → 「目前目錄不是 git repo，無法接續」並退出

### 步驟 2：找對應的 Obsidian 工作筆記
- Vault 路徑：`O:\我的雲端硬碟\AI_Project\00_colabrain\ColaBrain`
- 先讀 `每日筆記/` 下最近一筆工作紀錄
- 再找專案同名資料夾下的 `工作筆記.md`（若有）
- 用 `obsidian_read_note` 讀取
- 找不到 → 檢查 git log 最近一次 commit 來推斷進度

### 步驟 3：摘要「上次做到哪」
從工作筆記讀（精簡版、不要全文倒出來）：
- 「⏸️ 上次做到哪」段落
- 「➡️ 下一步」段落（若有）
- 「🕳️ 踩坑筆記」最近一筆（只在跟下一步直接相關時提）

### 步驟 4：檢查本地 git 狀態
```bash
git status --short
```
- clean → 「本地工作區乾淨」
- 有未 commit 變動 → 列出，問「要繼續還是放棄？」

### 步驟 5：檢查遠端（30 分鐘判斷）
```bash
[ -n "$(find .git/FETCH_HEAD -mmin -30 2>/dev/null)" ] || git fetch origin 2>/dev/null
BEHIND=$(git rev-list HEAD..origin/HEAD --count 2>/dev/null || echo 0)
```
- BEHIND > 0 → 提醒「遠端有 N 個新 commit，要 git pull 嗎？」**不主動 pull**
- BEHIND = 0 → 「本地是最新狀態」

### 步驟 6：報告 + 建議下一步
給結構化摘要：
```
📂 專案：<REPO_NAME>
📘 上次做到哪：<從工作筆記摘要 1-2 句>
🔧 本地 git：<clean / 有 N 個未 commit 變動>
🌐 遠端：<最新 / 落後 N commits，建議 git pull>
➡️ 建議下一步：
   1. <從工作筆記「下一步」第 1 項，或推斷>
   2. <可選：第 2 項>
要從哪個方向開始？
```
等使用者選方向，不要自己擅自繼續。

## 不該做的事
- ❌ 主動 `git pull`（會撞使用者本地未 commit 變動）
- ❌ 主動修改工作筆記（那是 `/收工` 的事）
- ❌ 在沒有工作筆記時硬建一個（先問使用者）
- ❌ 把工作筆記內容**全文倒出來**（要摘要、保持精簡）

## 與 /收工 skill 的對偶關係

| 面向 | `/收工` | `/開工` |
|------|---------|---------|
| 主要動作 | 摘要今天做什麼 | 摘要上次做什麼 |
| 工作筆記 | **寫入** | **讀出** |
| Git | `add` + `commit` + `push` | `status` + `fetch`（不 pull） |
| 何時觸發 | 結束對話前 | 新對話開頭 |
| 對外副作用 | 推 GitHub、改工作筆記 | **無**（只讀、只報告） |

**設計原則**：開工是「讀」、收工是「寫」。永不重疊、不衝突。
