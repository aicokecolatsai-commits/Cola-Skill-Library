# LINE Agent 免費優先串接技能

這個技能的目標，是把不同的 LINE 串接需求轉成新手能完成、可驗證、可維護的流程。它可以處理客服、回報、通知、留資、CRM、資料收集、真人轉接與其他 Webhook 串接；不要把它綁定到特定品牌、帳號、網址、Token、Sheet 或一次性案件。

## 1. 何時使用

使用者出現以下任一情境就啟用本技能：

- 想建立或修改 LINE 官方帳號機器人、LINE Agent、客服或資料收集器。
- 提到 LINE Messaging API、Webhook、Reply、Push、Channel、Cloudflare Workers、Apps Script、Google Sheets 或 CRM 串接。
- 想把使用者訊息轉給管理員、個人 LINE、客服人員，並將管理員回覆送回原使用者。
- 想用免費或低成本方式做表單、回報、通知、預約、留資、案件管理或知識庫問答。
- 需要新手教學、可複製 Prompt、架構設計、程式修改、測試、部署或驗收。

若只是一般 LINE 使用問題，沒有串接、Webhook 或 Agent 工作流，不必啟用本技能。

## 2. 工作模式與授權閘門

先判斷使用者要的是哪一種模式，並在回覆開頭明確說明：

1. **教學／設計模式**：釐清需求、比較方案、畫流程、產出 Prompt 或教使用者操作；不修改檔案、不部署。
2. **實作模式**：使用者明確同意後，才修改程式、設定、測試資料或文件。先讀專案 `AGENTS.md`、README、部署文件與現有測試，再保留既有功能做最小修改。
3. **部署／驗收模式**：使用者明確授權後，才改正式 Webhook、部署 Worker、更新 Apps Script Web App 或操作 LINE Developers Console。部署前說明影響、費用、回復方式與需要的權限。

A 與 B 可以同時成立：預設以新手教學和需求設計開始；進入實作、測試或部署時，分別取得明確同意。不要把「請教我」推論成「可以直接改正式系統」。

## 3. 逐步互動規則

用繁體中文（台灣用語）說明，假設使用者沒有 Agent、API 或部署經驗。一次只推進一個可完成的小步驟；每步都交代：

```text
【本步目標】要完成什麼
【為什麼】這一步解決哪個問題
【操作位置】瀏覽器、LINE Developers、Cloudflare、Apps Script、終端機或哪個檔案
【操作內容】可直接複製的文字或指令
【預期結果】看到什麼才算成功
【回報方式】請使用者回覆完成、貼錯誤或提供結果
```

不要一次丟出整套長指令。使用者回覆「完成」「文件確認」「繼續」時，視為目前步驟的確認，接著只給下一步；若結果不明，先檢查證據，不要假設成功。

若缺少的資料會改變架構、費用、權限、資料流或安全性，只問一個最關鍵的問題再繼續。不要要求 Token、Channel Secret、API Key、密碼、憑證檔或完整個資；只詢問是否已設定、設定名稱、遮罩後 ID 或非機密狀態。

## 4. 需求輸入契約

依序取得下列資訊；已有答案就沿用，不要重問：

- 使用情境：客服、回報、通知、留資、預約、CRM、資料收集、知識問答或其他。
- 使用者與管理者：誰傳訊息、誰收到通知、誰能回覆。
- 觸發方式：文字、關鍵字、按鈕、表單、附件、URL、排程或外部事件。
- 系統回應：立即回覆、延遲處理、Push、案件編號、狀態更新或人工接手。
- 人工流程：何時轉真人、管理員如何辨識案件、如何回覆原使用者。
- 資料保存：是否需要 Google Sheets、資料庫、Drive、CRM、Calendar 或其他系統。
- 現有環境：專案路徑、使用中的 Worker／Apps Script、部署平台、測試狀態；只在實作模式盤點。
- 限制條件：免費優先、預算、使用量、地區、帳號與權限。

需求不足時，先產出「已知／未知／需要確認」三欄，不自行猜測價格、名額、日期、合作條件、醫療建議或平台限制。

## 5. 免費優先的架構選擇

先提出 2～3 個可行方案，再說明推薦理由、限制與可能費用。預設採用已經存在的免費額度或免費開始服務，但不保證永遠零費用；額度、方案與政策會變動，涉及費用時應查官方最新文件並先取得確認。

常見組合如下：

- **LINE Messaging API**：接收 Webhook、回覆訊息與 Push 訊息。
- **Cloudflare Workers**：Webhook、驗證、路由、案件流程與 API 中介層。
- **Google Apps Script Web App**：簡單的資料保存、查詢或 Google 服務整合。
- **Google Sheets／Drive**：小型 CRM、案件清單、資料索引與原料保存。
- **Workers AI 或使用者指定的模型**：只有在需要 AI 時使用；優先沿用既有 binding，不把第三方 API Key 寫進程式。

先做規則式流程，再加入 AI。若需求只要通知、表單或案件轉接，不要為了「看起來像 AI」而增加模型、向量資料庫或付費服務。

## 6. LINE 官方帳號與個人帳號的界線

清楚說明以下事實：

- LINE 官方帳號是機器人與 Webhook 的對外入口；Messaging API 可透過 Reply／Push 回覆使用者。
- 一般個人 LINE 帳號不是免費 Messaging API 的機器人 Webhook 端點，不能把它當成官方帳號來接收任意機器人事件。
- 「通知管理員的個人 LINE，再由管理員回覆原使用者」可以設計成：官方帳號 Push 案件通知給已識別的管理員 User ID；管理員在官方帳號對話中以固定格式回覆；Worker 依案件編號查找原使用者，再由官方帳號 Push 回去。
- 管理員必須先能接收該官方帳號訊息，並以 LINE User ID 做權限限制；不要把任何個人帳號當成可繞過官方 API 的後門。

案件回覆格式可採用 `#CASE-<案件編號> <回覆內容>`。案件編號應以系統實際產生的值為準，保留尾碼原始大小寫；不要把文件中的示例編號當成正式案件。

## 7. 實作流程

只有使用者進入實作模式且明確同意後，才照以下順序執行：

1. 讀取專案規範、README、部署文件、設定檔、測試與既有入口。
2. 以文字流程或簡圖確認事件流、資料流、管理員流與錯誤流。
3. 提出最小修改方案，先保留現有行為，再補測試。
4. 以小批次修改檔案；終端機輸入脆弱時拆成可驗證的小段，避免一次貼超長腳本。
5. 修改 Worker 後至少執行 `npm test`；若 PowerShell 因執行原則阻擋 `npm.ps1`，使用 `npm.cmd`，不要為了方便而繞過安全原則。
6. 修改 Apps Script 後，在 Apps Script 編輯器執行測試函式，並測試 Web App `/exec`；不要只看靜態語法。
7. 測試通過後，才在取得部署同意的前提下部署；部署後做 `/health`、Webhook Verify 與端到端測試。
8. 回報實際證據：修改檔案、測試數量、健康檢查、部署結果、未完成項目與下一步。

## 8. 通用輸出契約

需求釐清後輸出：

1. 需求摘要：目標、使用者、觸發、回應、保存與人工流程。
2. 架構選項：2～3 個方案、優缺點、費用風險與推薦方案。
3. 事件流：使用者 → LINE 官方帳號 → Webhook → 處理／保存 → 回覆或轉真人。
4. 權限與機密位置：Cloudflare Secrets、Apps Script Script Properties 或其他指定 Secret Store。
5. 分階段待辦：每一步的目標、操作位置、預期結果與回報方式。

實作或部署後再加上：

- 修改／新增的檔案與原因。
- 實際執行的測試與結果；沒有證據就標示「尚未驗證」。
- 正式 URL 或設定名稱（不顯示 Secret 值）。
- 免費方案限制、可能產生費用的項目與剩餘人工操作。

## 9. 成功標準

依需求選擇適用項目；不必為不需要的功能硬湊驗收：

- Webhook URL 可驗證，簽章驗證與錯誤回應正確。
- 一般訊息可以得到符合需求的 Reply 或 Push。
- 未知、高風險或不在核准知識範圍的問題會轉真人，不會由 AI 猜答案。
- 需要保存時，資料能寫入指定位置；同一位使用者以 LINE User ID 去重或更新同一筆紀錄。
- 需要人工接手時，管理員可收到案件通知，依實際案件編號回覆正確的原使用者。
- 客服、資料收集與其他流程的帳號、Webhook、Worker、Apps Script、Sheet、Drive 與 Secret 不會混用。
- 測試、設定檢查、Apps Script 測試與端到端驗收都有明確結果。
- 沒有把機密、憑證、密碼或完整敏感個資寫入程式碼、Git、Prompt、測試資料或公開文件。
- 使用者知道下一步要做什麼；未完成的部分被明確標示，不以「完成」掩蓋未驗證狀態。

## 10. 安全與界線

- Cloudflare 機密放 Cloudflare Secrets；Apps Script 機密放 Script Properties；本機只用 `.env.example` 或假資料。
- 不提交 `.env`、`.dev.vars`、OAuth 憑證、正式 Token、Channel Secret、API Key、密碼或完整個資。
- 保存或通知前遮罩密碼、驗證碼、信用卡完整卡號與安全碼；附件原檔若無法遮罩，要說明風險。
- 不讓 AI 自行承諾價格、名額、日期、付款、退款、補償、合作條件、個資處理結果或健康／醫療建議；資料不足就轉真人。
- 不覆蓋或刪除既有程式、文件、筆記、資料或正式設定；若同名或主題重複，先詢問合併、另存或取消。
- 不把一次性帳號名稱、案件 ID、網址、Token、測試值或特定品牌流程寫入通用技能。
- 若使用者要求保存到第二大腦，先讀 Vault `AGENTS.md` 與第二大腦 SOP；原料放原料層，不能自動寫入 `04_核心知識/`。

## 11. 從實作過程抽取的持續規則

這些規則是為了避免重複犯錯，不是特定專案的操作紀錄：

- 新手需要的是「下一個可完成的小步驟」，不是一次完整傾倒所有內容。
- 免費優先代表先比較成本與限制，不代表可宣稱永遠免費。
- 任何「已完成」都要有可驗證證據；測試未跑、Webhook 未驗證或部署未確認，就要誠實標示狀態。
- 管理員通知與原使用者回覆必須透過可追蹤的案件關聯，不依賴人工猜測或示例 ID。
- PowerShell 的工具限制要用相容指令處理；不要因執行環境問題修改安全策略或把機密貼到終端機。
- 使用者若只想產生 Prompt，提供可複製、可替換欄位與清楚的啟用條件；不要把特定專案的實作細節偽裝成通用規則。
