# 📐 Ergo & PencilPlaybook: 人因設計心理學與反 AI 審美校準技能

> 專為追求頂級產品體驗的前端工程師與設計師打造。融合 **Hallmark 反 AI 罐頭感審美校準**、**PencilPlaybook 設計心理學核心規則** 與 **Noah 職場人因工程原則**，杜絕平庸廉價的 AI 生成感，打造符合人類直覺的高質感介面。

---

## 🎯 什麼時候啟用本技能？
- 當前端畫面感覺「很像 AI 做的（AI Slop）」、充斥無意義的漸層與假卡片時。
- 需要評估介面的易用性、認知負擔（Cognitive Load）與點擊效率時。
- 需要依據格式塔心理學、席克定律、費茨定律排查 UI 佈局缺陷時。
- 進行 UI 上線前的「Pre-flight 審美與人因校準檢查」時。

## 🚫 第一部：Hallmark 反 AI 視覺語病排查（Anti-AI Slop）

AI 生成網頁時極易陷入以下 7 大「廉價罐頭陷阱」，在輸出程式碼前**必須逐一清查並修正**：

### 1. 拒絕「紫色/藍粉漸層中毒症」（Purple/Pink Gradient Overdose）
- ❌ **AI 慣性**：所有按鈕、背景、文字標題無腦套用 `bg-gradient-to-r from-purple-500 to-pink-500`。
- ✅ **校準規則**：
  - 回歸明確的產品調性。企業級使用深邃冷灰（`slate-900`）、科技感使用精緻單色強對比、或採用低飽和質感的微漸層（`from-zinc-900 to-zinc-950`）。
  - 單一畫面中，高彩度強調色（Accent Color）佔比不應超過 5%。

### 2. 拒絕「卡片套卡片俄羅斯娃娃」（Card-in-Card Syndrome）
- ❌ **AI 慣性**：每個元素都套上外框、圓角、白色背景與陰影，造成資訊層級支離破碎。
- ✅ **校準規則**：
  - 使用**留白（Whitespace）**與**字體層級（Typography Hierarchy）**劃分區塊，而非盲目依賴框線與背景卡片。
  - 同一區塊內嚴禁嵌套超過 2 層以上的獨立邊框卡片。

### 3. 拒絕「無意義的假 3D 浮誇插圖與空洞高光」
- ❌ **AI 慣性**：插入無功能意義的 3D 泡泡、假立體火箭、發光星芒，畫面雜訊極大。
- ✅ **校準規則**：
  - 優先使用**真實產品介面預覽（Real UI Mockup）**、**極簡線條圖標（Lucide / Heroicons）**或**有意義的數據圖表**。

### 4. 拒絕「均等間距與喪失節奏感」（Flat Rhythm）
- ❌ **AI 慣性**：所有元素上下 margin 一律 `mb-4` 或 `p-6`，失去視覺呼吸節奏。
- ✅ **校準規則**：
  - 嚴格遵守 8pt 網格系統（8px, 16px, 24px, 32px, 48px, 64px, 96px）。
  - 相關內容緊湊（Gap-2/3），獨立區塊大氣舒展（Gap-12/16/24）。

## 🧠 第二部：PencilPlaybook 設計心理學核心法則

### 1. 席克定律 (Hick's Law) — 決策時間隨選項數量對數增長
- **介面規則**：
  - 一個頁面的核心主行動（Primary Action）**只能有 1 個**。
  - 次要行動使用幽靈按鈕（Ghost / Outline Button）或純文字連結。
  - 導航欄主選單最多保留 **5~7 個頂級項目**（符合米勒定律 7±2 記憶組塊）。

### 2. 費茨定律 (Fitts's Law) — 目標越大、距離越近，到達時間越短
- **介面規則**：
  - **行動按鈕熱區（Touch Target）**：移動端最小不得小於 `44x44px`（Tailwind `min-h-[44px] min-w-[44px]`）。
  - **拇指操作區（Thumb Zone）**：移動端重要 CTA 或底部導航應置於螢幕下方 1/3 自然可達區域。
  - **破除死角**：文字連結不可只有文字本身可點擊，必須加大 `padding` 擴展可點擊範圍。

### 3. 格式塔心理學 (Gestalt Principles)
- **接近法則 (Proximity)**：標題與其下方的內文距離（例如 `mt-2`），必須明顯小於該段落與上一區塊的距離（例如 `mt-8`）。
- **相似法則 (Similarity)**：所有同等層級的交互元素（例如次級標籤、篩選按鈕）必須保持完全一致的造型與回饋狀態。
- **共同區域法則 (Common Region)**：將邏輯相依的表單欄位放在同一個淺色背景或微弱框線分組中。

### 4. 視覺動線與眼動模型 (Visual Hierarchy & Scan Paths)
- **文字密集型頁面（Dashboard / 文章）**：採用 **F 型動線**，將關鍵數據、指標名稱靠左對齊，數值放大並加粗。
- **行銷與展示型頁面（Landing Page）**：採用 **Z 型動線**，引導視線：
  `Logo / 標題 (左上) → 登入/聯絡 (右上) → 核心插圖/痛點 (中央) → 轉換 CTA (右下)`。

## 🛡️ 第三部：Noah 人因工程視覺防疲勞規範

1. **對比度標準（WCAG 2.1 AA+）**：
   - 內文與背景對比度至少 4.5:1，大標題至少 3:1。
   - 避免純黑背景搭配 #FFFFFF（易造成人眼眩光與疲勞），建議使用 `bg-[#0B0F17]` 搭配文字 `text-zinc-200` 或 `text-zinc-300`。
2. **行高與字距（Legibility）**：
   - 內文字級建議：`text-base (16px)` 或 `text-sm (14px)`。
   - 內文行高必須設定為 `leading-relaxed (1.625)` 或 `leading-7 (1.75)`，單行字數控制在 60~75 字元之間（最佳閱讀寬度 `max-w-prose` 或 `max-w-2xl`）。

## 📋 Pre-flight UI 審美與人因檢查清單

- [ ] 是否消除了無意義的紫粉霓虹漸層？
- [ ] 核心 CTA 按鈕是否唯一且鮮明？
- [ ] 移動端按鈕點擊熱區是否 >= 44x44 px？
- [ ] 標題與內文的接近性是否明顯大於段落間距？
- [ ] 卡片是否有超過 2 層的無效嵌套？
- [ ] 內文閱讀寬度是否受限於舒適寬度（非全螢幕拉扯）？
- [ ] 黑暗模式下是否採用舒適的微柔和對比（非死白純黑）？
